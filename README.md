Консольные приложения **сервер** и **клиент** для передачи файлов по сети TCP/IP (IPv4). Реализованы на C++ под ОС Linux.

Сервер поддерживает одновременное обслуживание нескольких клиентов с помощью потоков (`pthread`). Клиент умеет как **получать** файл с сервера (`GET`), так и **отправлять** файл на сервер (`PUT`). Передача ведётся фиксированными порциями (размер настраивается). Прогресс выводится в процентах и байтах.

## Сборка

В проекте используется `Makefile`.

```bash
make            # собрать всё
make clean      # удалить собранные файлы

После сборки в текущей папке появятся:

    server_app – исполняемый файл сервера

    client_app – исполняемый файл клиента

    libfileops.so – библиотека для работы с файловой системой (раннее связывание)

    libprogress.so – библиотека для вывода прогресса (позднее связывание, загружается клиентом в рантайме)

Запуск сервера
bash

./server_app [-p <порт>]

Аргумент	Описание	По умолчанию
-p	номер порта для прослушивания	8080

Пример:
bash

./server_app -p 4040

После запуска сервер начинает слушать указанный порт и ожидает подключений.
Запуск клиента
bash

./client_app -src <источник> -dst <приёмник> [-p <порт>] [-chunk <размер>]

Аргументы
Аргумент	Описание	Обязательный	По умолчанию
-src	источник файла (локальный путь или IP:путь)	да	–
-dst	приёмник файла (локальный путь или IP:путь)	да	–
-p	порт сервера	нет	8080
-chunk	размер порции передачи в байтах (положительное число)	нет	1024
Режимы работы клиента

Автоматически определяются по формату аргументов:

    GET (получить файл с сервера) – если -src имеет вид IP:путь, а -dst – локальный путь.

        Клиент подключается к серверу по указанному IP и порту, запрашивает файл по пути на сервере и сохраняет его локально.

    PUT (отправить файл на сервер) – если -src – локальный путь, а -dst имеет вид IP:путь.

        Клиент подключается к серверу, читает локальный файл и передаёт его на сервер, который сохраняет его по указанному пути.

Если ни один из аргументов не содержит IP:путь, программа завершится с ошибкой.
Примеры
Получение файла с сервера (GET)
bash

# Сервер слушает порт 4040
./server_app -p 4040

# На сервере уже есть файл /tmp/file_src
# Клиент скачивает его порциями по 128 байт и сохраняет в /tmp/file_dst
./client_app -p 4040 -chunk 128 -src 127.0.0.1:/tmp/file_src -dst /tmp/file_dst

Отправка файла на сервер (PUT)
bash

# Сервер слушает порт 4040
./server_app -p 4040

# Клиент отправляет локальный файл /tmp/my_file на сервер
# Сервер сохранит его как /tmp/remote_file
./client_app -p 4040 -chunk 128 -src /tmp/my_file -dst 127.0.0.1:/tmp/remote_file

Протокол обмена

Клиент и сервер общаются по TCP. После установки соединения клиент отправляет запрос следующего формата:
Поле	Размер (байт)	Описание
cmd	1	'G' – GET (получить файл), 'P' – PUT (отправить файл)
chunk_size	4	размер порции в байтах (сетевой порядок)
path_len	2	длина пути к файлу на сервере (сетевой порядок)
path	path_len	путь к файлу на сервере (без завершающего нуля)
GET (клиент забирает файл)

    Сервер после получения запроса открывает файл по указанному пути.

    Если файл не найден или ошибка – отправляет размер 0 и закрывает соединение.

    Иначе отправляет размер файла (8 байт, сетевой порядок), затем читает файл порциями по chunk_size и отправляет их клиенту.

    Клиент принимает размер, затем принимает данные порциями, записывает их в локальный файл и показывает прогресс.

PUT (клиент отправляет файл)

    Клиент после запроса отправляет размер локального файла (8 байт, сетевой порядок).

    Затем читает локальный файл порциями по chunk_size и отправляет их серверу.

    Сервер принимает размер, затем принимает данные порциями и записывает их в файл по указанному пути (создаёт/перезаписывает).

Внутреннее устройство
Библиотеки

    libfileops.so – файловые операции (открытие, чтение, запись, закрытие, получение размера). Используется и сервером, и клиентом. Линкуется на этапе сборки (раннее связывание).

    libprogress.so – функция print_progress(size_t sent, size_t total) для вывода прогресса. Клиент загружает эту библиотеку через dlopen и получает указатель на функцию через dlsym (позднее связывание). Если загрузка не удалась, используется резервная функция (только вывод байтов).

Сервер

    Использует pthread для создания отдельного потока на каждого клиента.

    Потоки отсоединены (pthread_detach), чтобы не ждать их завершения.

    Список активных клиентских сокетов защищён мьютексом для корректного закрытия при завершении.

    Обработчик SIGINT закрывает слушающий сокет и все клиентские сокеты, затем сервер завершается.

Клиент

    После парсинга аргументов определяет режим (GET/PUT).

    Подключается к серверу, отправляет запрос.

    В цикле передаёт/принимает данные порциями, обновляя прогресс.

    При получении SIGINT (Ctrl+C) закрывает сокет, устанавливает флаг running = 0, что прерывает цикл передачи.

    При GET неполный файл удаляется (unlink), чтобы на диске оставался только полностью переданный файл.

Особенности реализации

    Прогресс передачи – клиент выводит динамически обновляемую строку в формате
    Progress: <передано> / <общий размер> bytes (<проценты>%).

    Библиотека прогресса – загружается динамически, что демонстрирует позднее связывание.

    Файловые операции – вынесены в отдельную библиотеку (раннее связывание) для удобства поддержки.

    Прерывание по Ctrl-C – клиент и сервер корректно закрывают TCP-соединения. Клиент не сохраняет неполный файл на диск (при получении) – удаляет его.

    Многопоточность – сервер создаёт отдельный поток для каждого клиента, что позволяет обслуживать несколько соединений одновременно.

    Надёжность – все сетевые операции используют функции sendAll/recvAll, гарантирующие полную передачу данных (или сигнализирующие об ошибке).

Устранение неполадок
Сообщение об ошибке	Вероятная причина и решение
Server file not found or empty	Запрашиваемый файл отсутствует на сервере. Создайте его или проверьте путь.
error while loading shared libraries: ...	Библиотека не найдена. Установите LD_LIBRARY_PATH или пересоберите с rpath.
Address already in use	Порт уже занят. Укажите другой порт или завершите процесс, использующий этот порт.
Ошибка при компиляции undefined reference	Убедитесь, что библиотеки собраны и линкуются правильно. Выполните make clean && make.
Клиент зависает при передаче	Проверьте, что сервер запущен и доступен по сети. Используйте telnet или nc для проверки соединения.
Запуск с динамическими библиотеками

После сборки библиотеки (libfileops.so и libprogress.so) лежат в текущей папке. Чтобы приложения могли их найти, задайте переменную окружения LD_LIBRARY_PATH:
bash

export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
